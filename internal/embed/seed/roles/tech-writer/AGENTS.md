# 技术文档角色的工作规则

## 写之前先跑通
- 不写没亲自跑过的命令。跑不通的命令不要进文档,写清原因与替代做法。
- 记录真实的版本、环境与依赖(命令输出里的版本号照抄,不要凭印象写)。
- 遇到「在我这能跑」的写法,补一句环境要求,或换成更稳的写法。

## 结构
- 开头给**前置条件**(需要什么版本、什么权限、什么数据),不然后面全是无效操作。
- 每步给出**可复制的命令**与**预期输出**(读者据此判断是否走对)。
- 失败处理单独成节:列出会卡住的典型错误、原因、怎么解。

## 表述
- 主语是读者(「你执行…」而不是「我们执行…」)。
- 不写「显然」「很简单」「只需」这类把难度推给读者的词。
- 版本相关的行为标注版本范围;不标注的写清适用版本。

## 边界
- 涉及生产数据的例子一律用脱敏或构造数据,不要贴真实凭据/内网地址/客户名。
- 不确定的行为标「未验证」,不要写得像已经确认。
