# 前置条件清单

「装不上」的排查成本里,大部分花在**没写的前置条件**上。清单的价值不在
列得多,而在每一条都能**一句话确认**。

## 六个维度

| 维度 | 要写清 | 确认方式 |
|---|---|---|
| **版本** | 最低版本;是否只测过某几个版本 | 给查版本的命令 |
| **权限** | 需要什么权限、能不能不用管理员 | 给验证权限的命令 |
| **依赖** | 外部程序/服务,以及**拿不到会怎样** | 给检查存在性的命令 |
| **数据** | 需要预置什么数据/凭据,格式是什么 | 给格式样例 |
| **容量** | 磁盘、内存,并发的量级 | 给出实测值而非「充足」 |
| **网络** | 能否离线;需要放行哪些域名/端口 | 给出清单 |

## 每条前置条件三行

1. **要求**:一句话,含量。
2. **怎么确认**:一条能跑的命令或一个能看的界面。
3. **不满足时**:具体怎么办(装什么、找谁、能不能跳过)。

第三行是给「已经装不上的人」写的,也是清单里最省时间的一行。

## 版本口径

- 写**最低**版本,并列出**实际测过**的版本(两者不同,只写一个就是误导)。
- 依赖项也要版本(「Node 22 或更高」不如「Node 22.x,测过 22.6/22.11」有用)。
- **不要写「最新版」** —— 读者读到时最新版已经变了。

## 离线与代理

如果产品可能离线部署,必须写清:

- 哪些功能**必须有网**(并说明失败形态:报错还是降级);
- 镜像/代理怎么配;
- 凭据从哪来(环境变量?配置文件?权限是什么?)。

## 容量给实测

写「磁盘 ≥10GB」不如写「实测安装后 320MB;日志按天轮转,一年约 2GB」——
后者让读者能自己算。

## 最小示例

某命令行工具的部署前置清单:

| 要求 | 怎么确认 | 不满足时 |
|---|---|---|
| Linux/macOS ≥ 内核 4.15(macOS 12+) | `uname -r` | 旧内核请用 v1.x 分支 |
| 需可写的数据目录(默认 `~/.gah-data`) | `test -w ~/.gah-data || mkdir -p ~/.gah-data` | 不可写就设 `GAH_DATA_DIR=/你的目录`(**不要**改用 root 跑) |
| 联网访问 `api.example.com:443`(仅模型调用需要) | `curl -sI https://api.example.com` | 内网部署需配代理 `HTTPS_PROXY`;不联网时除模型调用外功能可用 |
| 一个 API 凭据 | 文件存在且权限 600:`ls -l ~/.gah-data/config/provider.yaml` | 没有就复制模板并填 key,`chmod 600` |

实测:安装后占用 41MB;单会话日志约 30MB/千轮,默认保留 30 天。
测试过的版本:1.2.x(当前)、1.3.x(预览)。1.0.x 未测。
