# 可复制命令 + 预期输出

文档里最贵的错误是**跑不通的命令**:读者复制了、失败了、然后不再相信整篇
文档。每条命令都要当成**会被执行**的东西写。

## 每条命令三样

1. **命令本身**:能直接复制的完整一行(不写 `$`、`>` 这类提示符)。
2. **预期输出**:至少给关键那几行,让读者能对照「对不对」。
3. **它会改动什么**:写文件?装东西?发网络请求?删数据?

第三样最常被漏。**会改系统状态的命令必须显式标注**,并在破坏性的那条前
给出更安全的替代。

## 五条纪律

- **占位符统一写法**:`<你的目录>`、`<TOKEN>`,一眼能看出要替换;不要用
  `your_path` 和 `xxx` 混着来。
- **一条命令一件事**:不要用 `&&` 串三条不同目的的命令 —— 读者没法只跑前一条。
- **不用需要 root 的命令**而不说明;要用的写清权限范围。
- **不给未验证的命令**。没跑过的命令标出来(「以下为待验证」),或别写。
- **不复用易错参数**:隐藏标志、能删文件的通配,不要出现在示例里。

## 危险命令的写法

| 危险度 | 做法 |
|---|---|
| 只读 | 直接给 |
| 写入用户目录 | 标注「会创建/覆盖 X」 |
| 改全局配置/装系统包 | 先给只读检查命令(版本、是否已装),再给安装命令 |
| 删数据/重置 | **不作为默认步骤给**;放进单独的「危险操作」小节,写清影响范围与回滚方式 |

## 失败要能自诊断

每条命令后面给**失败时怎么办**:权限不足怎么办、命令不存在说明缺什么、
网络不通有什么替代。读者遇到报错时最想要的就是这一句。

## 验收

交付前从头跑一遍:复制粘贴,不做任何手工调整。如果必须手工调整步骤,
**先改文档,再交付**。

## 最小示例

原写:

```
$ gah init
```

改为:

```bash
gah init
```

预期输出:

```
已创建数据根 /Users/me/work/gah-data
已释放 12 个预置角色
下一步:gah  (直接进入对话)
```

它会改动:在**当前工作目录**下创建 `gah-data/`(配置、凭据、会话、记忆都在
里面)。已存在时不会覆盖,会提示改用 `--force`。

失败时怎么办:

- `permission denied` ⇒ 当前目录不可写,换到有写权限的目录(文档不要建议
  直接 `sudo`)。
- `gah: command not found` ⇒ 安装后需重开终端,或确认安装目录在 PATH 里。
