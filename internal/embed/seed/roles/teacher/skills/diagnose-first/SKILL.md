# 先诊断再讲原理

「讲原理」是学习里最常见的无效动作:对方卡在第 2 层,你从第 0 层开始讲,
于是他更卡了。**先定位卡点,再决定讲什么**。

## 四层卡点

| 层 | 症状 | 该讲什么 |
|---|---|---|
| **概念** | 不知道这个词指什么 | 定义 + 一个具体例子 |
| **机制** | 知道是什么,不知道怎么会这样 | 执行过程/流程图/边界条件 |
| **适用** | 知道原理,不知道什么时候用 | 判据:什么场景用它、什么场景不用 |
| **熟练** | 会用,总出错 | 陷阱清单 + 练习 |

**诊断方法**:让对方用自己的话复述一遍,或答一个只可能用某层才能答的问题。
答错在哪一层,卡点就在哪一层。

## 讲的顺序

1. **先答「你现在卡在哪」** —— 一句话确认,别默认。
2. **只讲那一层**,不铺垫后面的层。
3. **用一个具体例子**收尾,并让对方复述。
4. 确认过了再进下一层。

## 例子要具体到能跑

抽象例子(「想象一个盒子」)讲完对方还是不会。例子要:

- 有真实的输入和输出;
- **能当场跑一遍**(代码/命令/可数的数);
- 失败时是什么样子。

## 常见错误

- **一次讲三层**:从概念到机制到最佳实践,对方只接住第一层。
- **用术语解释术语**:「异步是因为它是非阻塞的」—— 双方都不懂。
- **跳过「适用」层**:会讲原理不会判断用不用,是绝大多数「学完还是不会」的原因。
- **默认对方会了**:同名概念在不同体系里含义不同(比如「事务」)。

## 也要能判断「不该现在讲」

- 对方当前任务是熟练层,补概念是**打断**,延后。
- 这块知识此刻用不到,**标记为待学**,先给最小够用的部分。

## 最小示例

学生:「我看不懂这段递归代码。」

诊断(问一句):「你卡在哪 —— 是不知道递归函数怎么调用自己,还是知道调用方式
但看不出它什么时候停?」

答:「知道调用方式,但看不出为什么这里会停。」

⇒ 卡在**机制层**,不讲函数式基础,直接讲**基例 + 递归出口**:

> 递归函数停下来靠的是**基例**(base case):某个输入直接返回值,不再往下调。
>
> 这段代码:参数为 1 时直接返回 1(基例);否则调用自己,参数减 1。
> 所以调用栈是 f(4) → f(3) → f(2) → f(1) → 返回,深度 4,不会无限下去。
>
> 你可以跑一遍:在第 2 行加个打印,看它被调用了几次、参数是什么。

然后确认:让他说出「这里为什么不会死循环」—— 能答出「因为 f(1) 直接返回」,
机制层过了。下一步才进「递归改循环」的熟练层。
